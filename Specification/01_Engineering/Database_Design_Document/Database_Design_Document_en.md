# Database Design Document

**Project:** vLearn2 (VFLS) · **Version:** 1.0 · **Date:** 2026-05-22
**DBMS:** PostgreSQL 16 · **ORM:** TypeORM 0.3

---

## 1. Overview

The vLearn2 database is the system of record for all persistent data.
It is accessed exclusively by the NestJS backend via TypeORM (26
entities). Conventions:

- **Primary keys:** UUID, generated by `gen_random_uuid()` (pgcrypto).
- **Table prefix:** `vl_` on most tables (the `users` table is an
  exception).
- **Localized text:** stored as JSONB (`I18nText`) for multi-language
  content.
- **Timestamps:** `timestamptz`.
- **Schema evolution:** 13 ordered TypeORM migrations; tracked in
  `vl_migrations`.
- **Seeding:** a seed runner loads baseline achievements, app-config,
  courses, personas, and scenarios.

## 2. Entity-relationship overview

```
users 1───1 vl_user_info

vl_admins 1───N vl_admin_refresh_tokens

users N───M vl_news_posts    (via vl_news_read_status)
```

## 3. Domain groups

### 3.1 Identity & access

**`users`** — learner account. `id` (PK, uuid), `password_hash`
(varchar 255, not selected by default), `name` (varchar 100), `cid`
(varchar 10, nullable), `cid_username` (varchar 50, nullable),
`gender` (varchar 20, default `unspecified`), `created_at`,
`updated_at`. One-to-one `info` → `vl_user_info` (eager, cascade).

**`vl_user_info`** — learner profile. `user_id` (PK/FK → `users`,
`ON DELETE CASCADE`), `email` (varchar 255, unique), `avatar_emoji`,
`native_language`/`ui_language` (default `en`), `current_level`
(smallint, default 1), `xp_total` (int), `streak_days` (smallint),
`last_active_date` (date), `active_persona_id` (uuid), `active_theme`,
`onboarding_done` (bool), `role` (`UserRole`), `status`
(`UserStatus`), `suspended_until`, `suspended_reason`,
`leaderboard_opt_in` (bool, default true). Indexed on `xp_total`,
`streak_days`.

**`vl_refresh_tokens`** — `id` (PK), `user_id`, `token_hash`
(SHA-256), `expires_at`, `created_at`.

**`vl_admins`** — staff account. `id` (PK), `email` (unique),
`password_hash` (not selected), `display_name`, `role` (`AdminRole`,
default `admin`), `status` (`AdminStatus`, default `active`),
`last_login_at`, `created_at`, `updated_at`.

**`vl_admin_refresh_tokens`** — `id`, `admin_id`, `token_hash`,
`expires_at`, `created_at`.

**`vl_admin_permissions`** — composite PK (`user_id`, `permission`),
`granted_by`, `granted_at`.

**`vl_admin_audit_log`** — `id` (PK), `user_id` (actor, nullable),
`action`, `target_type`, `target_id`, `old_value`/`new_value`/
`metadata` (jsonb). Three composite indexes for query performance.

### 3.2 Learning content

**`vl_personas`** — `id` (PK), `slug` (unique), `name`, `accent`,
`style`, `specialties` (jsonb string[]), `gradient_from`/`gradient_to`,
`rive_asset`, `image_url`, `image_storage_key`, `is_active` (default
true), `gender` (`female`/`male`/`neutral`), `voice_id`.

**`vl_categories`** — `id` (PK), `slug` (unique, immutable), `title`
(jsonb I18nText), `description` (jsonb), `order_index`, `is_active`,
`created_at`.

**`vl_scenarios`** — `id` (PK), `slug` (unique), `category` (slug,
denormalized), `category_id` (FK → `vl_categories`, `ON DELETE
RESTRICT`), `difficulty` (smallint), `title`/`description`/
`scene_description`/`user_role`/`tutor_role` (jsonb I18nText),
`objectives` (jsonb), `key_phrases` (jsonb), `estimated_minutes`,
`xp_reward`, `order_index`, `image_*`, `author_id`, `status`
(`ScenarioStatus`), `published_at`, `created_at`. Indexed on `status`,
`category`, `difficulty`, `category_id`.

**`vl_courses`** — `id` (PK), `slug` (unique), `title`/`description`
(jsonb), `level_range`, `total_xp`, `order_index`, `image_url`,
`status` (`CourseStatus`), `published_at`.

**`vl_course_scenarios`** — `id` (PK), `course_id`, `scenario_id`,
`order_index`. Join table for the courses↔scenarios many-to-many.

**`vl_prompt_templates`** — `id` (PK), `kind` (`PromptKind`, unique),
`label`, `description`, `template` (text), `is_active`, `updated_at`.

### 3.3 Conversations & scoring

**`vl_conversation_sessions`** — `id` (PK), `user_id`, `scenario_id`
(nullable; null = free talk), `persona_id`, `mode`
(`ConversationMode`), `status` (`SessionStatus`, default `active`),
`started_at`, `ended_at`, `duration_seconds`, `turn_count`,
`word_count`, `xp_earned`.

**`vl_conversation_messages`** — `id` (PK), `session_id`, `role`
(`MessageRole`), `content` (text), `sequence` (int), `audio_url`,
`created_at`.

**`vl_session_scores`** — `id` (PK), `session_id` (unique),
`overall_score` and per-skill scores (`pronunciation`, `fluency`,
`vocabulary`, `grammar`, `engagement`, `listening` — smallint,
nullable), per-skill `*_metrics` (jsonb), `strengths`/`improvements`
(text[]), `ai_feedback` (text), `evaluator_versions` (jsonb),
`computed_at`.

### 3.4 Progress & gamification

**`vl_user_progress`** — `id` (PK), `user_id` (unique),
`sessions_total`, `sessions_this_week`, `minutes_spoken_total`,
`minutes_spoken_this_week`, `words_spoken_total`,
`scenarios_completed`, `current_streak`, `longest_streak`,
`level_history` (jsonb), `updated_at`.

**`vl_skill_snapshots`** — `id` (PK), unique (`user_id`,
`snapshot_date`), `pronunciation`/`fluency`/`listening` (nullable),
`vocabulary`/`grammar` (default 0), `sessions_in_window`, `confidence`
(default 50).

**`vl_user_scenario_completions`** — `id` (PK), `user_id`,
`scenario_id`, `best_score`, `completion_count` (default 1),
`first_completed_at`, `last_completed_at`.

**`vl_achievements`** — `id` (PK), `key` (unique), `title`/
`description` (jsonb), `icon`, `xp_reward`, `condition_type`,
`condition_value`.

**`vl_user_achievements`** — composite PK (`user_id`,
`achievement_id`), `earned_at`.

### 3.5 Platform

**`vl_app_config`** — `key` (PK, varchar 100), `value` (jsonb),
`value_type` (`AppConfigValueType`), `category` (`AppConfigCategory`),
`description`, `default_value` (jsonb), `is_visible_to_app` (default
true), `updated_at`, `updated_by`.

**`vl_news_posts`** — `id` (PK), `slug` (unique), `title`/`body`
(jsonb), `summary` (jsonb), `image_*`, `author_id`, `status`
(`NewsStatus`, default `draft`), `pinned` (bool), `published_at`,
`created_at`, `updated_at`.

**`vl_news_read_status`** — composite PK (`user_id`, `news_post_id`),
`read_at`.

**`vl_guard_violations`** — `id` (PK), `user_id`, `session_id`
(nullable), `attempted_content` (text), `matched_terms` (text[]),
`severity` (`GuardSeverity`), `language`, `source` (`GuardSource`),
`user_acknowledged_warn` (bool), `created_at`.

**`vl_uploaded_files`** — `id` (PK), `storage_key` (unique),
`original_filename`, `mime_type`, `size_bytes`, `width`/`height`,
`content_hash` (varchar 64), `reference_count` (int, default 1),
`uploader_id`, `folder`, `storage_provider`, `created_at`.

## 4. Enumerations

| Enum | Values |
|------|--------|
| `UserRole` | `user`, `admin`, `superadmin` |
| `UserStatus` / `AdminStatus` | `active`, `suspended`, `deleted` |
| `AdminRole` | `admin`, `superadmin` |
| `ScenarioStatus` / `CourseStatus` / `NewsStatus` | `draft`, `published`, `archived` |
| `ConversationMode` | `chat`, `face` |
| `SessionStatus` | `active`, `completed`, `abandoned` |
| `MessageRole` | `user`, `assistant` |
| `GuardSeverity` | `block`, `warn` |
| `GuardSource` | `client`, `server` |
| `PromptKind` | `tutor_system`, `grammar`, `feedback` |
| `AppConfigCategory` | `home`, `evaluation`, `progress`, `conversation`, `scenarios`, `settings`, `system` |
| `AppConfigValueType` | `boolean`, `string`, `number`, `object`, `array` |

Enumerated values are stored as `varchar` and constrained at the
application layer, not as native PostgreSQL `ENUM` types.

## 5. Referential integrity

- `vl_user_info.user_id` → `users.id` — `ON DELETE CASCADE`.
- `vl_scenarios.category_id` → `vl_categories.id` — `ON DELETE
  RESTRICT` (a category in use cannot be deleted; the API returns
  `409`).
- Conversation messages and scores are logically owned by their
  session.

## 6. Indexing summary

| Table | Indexed columns | Purpose |
|-------|-----------------|---------|
| `vl_user_info` | `xp_total`, `streak_days` | Leaderboard ranking |
| `vl_scenarios` | `status`, `category`, `difficulty`, `category_id` | Catalog filtering |
| `vl_admin_audit_log` | 3 composite indexes | Audit search |
| `vl_skill_snapshots` | unique (`user_id`,`snapshot_date`) | One snapshot per day |

## 7. Migrations & seeding

13 migration files span the initial schema through the `vl_` prefix
introduction, the separation of admins into their own table, persona
gender/voice fields, prompt templates, and categories. The seed runner
(`run-seeds.ts`) is idempotent and populates reference content.
Development databases are provisioned via `docker-compose.yml`
(`postgres:16-alpine`).
