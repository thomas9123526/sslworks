# 테스트 요약 보고서

**프로젝트:** vLearn2 (VFLS) · **보고서 버전:** 1.0 (기준선)
**작성일:** 2026-05-22

> **본 문서의 상태.** 본 문서는 저장소에 존재하는 테스트 자산을
> 기술하는 **시점 기준선**이며, 완전히 실행된 테스트 캠페인의 결과가
> 아니다. 현재 자동화된 것과 남은 것을 기록한다. 실행된 각 테스트
> 주기 후 §4에 실행 결과를 채워 본 보고서를 재생성하라.

---

## 1. 목적 및 범위

본 보고서는 네 개 서브시스템(백엔드, 관리자 패널, Flutter 앱,
DataManage)에 걸친 vLearn2의 테스트 상태를 요약한다. 테스트 명세서
(테스트 계획) 및 상세 테스트 케이스 문서의 동반 문서이다.

## 2. 테스트 근거

- 요구사항 명세서(`FR-*`, `NFR-*`).
- 테스트 명세서(`TC-*` 카탈로그, 전략, 커버리지 목표).
- 상세 테스트 케이스(실행 가능 케이스).
- 요구사항 추적 매트릭스.

## 3. 자동화 테스트 자산 (현재 구축 상태)

| 서브시스템 | 프레임워크 | 존재하는 테스트 파일 | 커버 범위 |
|-----------|-----------|----------------------|-----------|
| 백엔드 | Jest, supertest | `ai/prompt-builder.service.spec.ts`, `guard/content-guard.service.spec.ts`, `test/app.e2e-spec.ts` | 프롬프트 빌더 로직, 콘텐츠 가드 로직, `GET /health` 스모크 |
| 관리자 패널 | Jest | `lib/__tests__/env.test.ts`, `flag-catalog.test.ts`, `utils.test.ts` | 순수 `lib/` 유틸리티 |
| Flutter 앱 | `flutter_test` | `datapack/installer_test.dart`, `datapack/unpack_test.dart`, `guard/content_guard_test.dart`, `storage/model_registry_test.dart` | datapack 설치/해제, 콘텐츠 가드, 모델 레지스트리 |
| DataManage | C++ 스모크 바이너리 | `manifest_smoke_test.cpp`, `packer_smoke_test.cpp`, `session_smoke_test.cpp` | 매니페스트·패커·세션 스모크 점검 |

| _(대기)_ | 관리자 패널 | — | — | — | — | `npm test` 실행 |

브랜치를 배포 브랜치(`main`)와 정렬하라.

## 5. 커버리지 평가

### 5.1 현재 커버 범위

- 백엔드: 프롬프트 빌더 및 콘텐츠 가드 로직; 헬스 라이브니스.
- 관리자 패널: 구성/환경 및 플래그 카탈로그 유틸리티.
- Flutter: `.ddp` 설치/해제, 콘텐츠 가드, 모델 레지스트리.
- DataManage: 매니페스트/패커/세션 스모크 점검.

### 5.2 주요 격차 (아직 미자동화)

| 영역 | 위험 |
|------|------|
| 백엔드 인증 및 토큰 회전 | 높음 |
| 관리자 RBAC / 권한 시행 | 높음 |
| 회화 및 채점 흐름(AI 대체 포함) | 높음 |
| 관리 변경 + 감사 로그 원자성 | 높음 |
| 백엔드 컨트롤러(대부분의 엔드포인트) | 높음 |
| Flutter 화면(위젯 테스트) | 중간 |
| Flutter 인증 상태 기계 및 라우터 리디렉션 | 중간 |
| 관리자 패널 컴포넌트 / 페이지 | 중간 |
| 오프라인 캐시 동작 | 중간 |

이는 테스트 명세서의 평가와 일치한다: 커버리지는 얕고 순수 로직
단위에 치우쳐 있다.

## 6. 미해결 요구사항 검증

요구사항 추적 매트릭스는 모든 `FR-*`/`NFR-*`를 테스트 케이스에 매핑
한다. 본 기준선 시점에 대부분의 케이스는 **정의되었으나 아직 미자동화**
상태이다. 우선순위 검증 작업(테스트 명세서 §7.2):

1. 백엔드 인증 및 RBAC 통합 테스트.
2. AI 대체 경로를 포함한 회화 및 채점 흐름.
3. 관리 변경 + 감사 원자성.
4. Flutter core 로직 및 핵심 위젯 테스트.

## 7. 결함

본 기준선에 대해 공식 결함 로그는 수립되지 않았다. 알려진 구현 격차
(플레이스홀더 AI 세션 시작, 비활성화된 gzip 차단 스위치, 디버그 키
서명 Android 릴리스, 개방형 관리자 가입, CI 브랜치 불일치)는 시스템
설계 명세서 §11과 프로젝트 및 리스크 관리 계획의 리스크 등록부에서
엔지니어링 항목으로 추적된다.

## 8. 결론 및 권고

vLearn2는 견고한 소수의 단위 테스트를 가지고 있으나 **핵심 비즈니스
로직에 대한 의미 있는 커버리지가 없다**. v1.0 릴리스 강화 마일스톤
이전에 테스트 명세서 §7.2 격차 해소 계획을 실행한 후, 실제 실행
결과를 §4에 채워 본 보고서를 재생성하라. P1 테스트 케이스 실패는
릴리스 차단 항목으로 취급하라.
