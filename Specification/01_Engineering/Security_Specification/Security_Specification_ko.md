# 보안 명세서 및 위협 모델

**프로젝트:** vLearn2 (VFLS) · **버전:** 1.0 · **작성일:** 2026-05-22

---

## 1. 목적 및 범위

본 문서는 vLearn2의 보안 아키텍처를 기술하고, STRIDE 모델로 위협을
분석하며, 구현된 통제를 나열하고, 알려진 약점을 완화 지침과 함께
기록한다. 백엔드 API, 관리자 패널, Flutter 앱, DataManage 서명 체인을
다룬다.

## 2. 보안 아키텍처

### 2.1 인증

- **이중 액터 JWT.** 단일 JWT 구조가 `sub`, 신원 클레임, `role`,
  `permissions[]`, 그리고 `actor` 구분자(`user` | `admin`)를 담는다.
  가드는 `actor`로 `sub`가 어느 테이블을 가리키는지 판단한다.
- **액세스 토큰:** HS256 서명, 단기(기본 15분).
- **리프레시 토큰:** 무작위 48바이트 비밀값, SHA-256 해시로만 저장,
  1회용(매 갱신 시 회전), 기본 수명 7일. 학습자와 관리자는 별도 토큰
  테이블 사용.
- **비밀번호:** bcrypt(10라운드). 학습자 최소 6자; 관리자 최소 12자
  + 대소문자 + 숫자.

### 2.2 인가

- 전역 `JwtAuthGuard`가 `@Public()` 데코레이터가 없는 한 모든 라우트를
  보호한다.
- 관리자 라우트는 추가로 `PermissionGuard`를 거치며, 약 40개 권한 키
  카탈로그에 대해 `@RequirePermission(...)`을 시행한다.
- `superadmin`은 개별 권한 검사를 우회한다(`permissions: ['*']`).
- 개인정보 민감 권한(예: 대화록 조회, 역할 편집, 계정 삭제, 모든
  `admins.*`)은 서브 관리자에게 부여 불가로 표시된다.

### 2.3 전송

- nginx에서 TLS 종단; `helmet`이 보안 헤더를 추가한다.
- CORS는 `CORS_ORIGINS` 허용 목록으로 제한되며 `credentials: true`.
- `ThrottlerGuard`를 통한 전역 속도 제한(기본 60초당 120요청).

### 2.4 데이터 보호

- 비밀값은 환경 변수로 공급되며, 예시 파일에는 플레이스홀더만 포함된다.
- 비밀번호 해시는 기본 쿼리 선택에서 제외된다(`select: false`).
- 업로드 파일은 MIME 타입과 크기로 검증되며 콘텐츠 해시와 함께
  저장된다.

### 2.5 공급망 — DataManage `.ddp`

- 음성 모델 번들은 DataManage 도구가 암호학적으로 서명한다.
- Flutter 앱은 루트 CA(`assets/datamanage/root_ca.crt`)를 고정하고
  설치 전 번들 서명을 검증한다; 해제는 백그라운드 아이솔레이트에서
  실행된다.

## 3. 신뢰 경계

```
[ 학습자 기기 ] ──TLS──► [ nginx ] ──► [ 백엔드 ] ──► [ PostgreSQL ]
[ 관리자 브라우저 ] ──TLS──► [ nginx ] ──► [ 관리자 패널 ] ──► [ 백엔드 ]
                                          [ 백엔드 ] ──► [ AI 제공자 ]
[ DataManage(오프라인) ] ──서명──► .ddp ──► [ Flutter 앱 검증 ]
```

경계: 기기↔nginx(비신뢰 네트워크), nginx↔서비스(내부),
백엔드↔AI 제공자(외부 제3자), DataManage↔앱(오프라인 서명 산출물).

## 4. STRIDE 위협 분석

| 위협 | 벡터 | 완화 | 잔여 위험 |
|------|------|------|-----------|
| **위장(Spoofing)** | 자격 증명/토큰 탈취 | bcrypt, 짧은 액세스 토큰 TTL, 1회용 리프레시 토큰 | 관리자 패널 XSS를 통한 토큰 탈취 — §5.2 |
| **변조(Tampering)** | 요청 변조; `.ddp` 변조 | 검증 파이프, TLS, 서명 번들 + 고정 CA | 낮음 |
| **부인(Repudiation)** | 관리자가 행위 부인 | 불변 `vl_admin_audit_log`, 트랜잭션 내 기록 | 낮음 |
| **정보 노출** | 스니핑; 과도한 응답 | 전 구간 TLS; 해시 `select:false`; CORS 허용 목록 | HTTP/HTTPS 혼합 설정 오류 — §5.3 |
| **서비스 거부** | 요청 폭주; 대용량 업로드 | `ThrottlerGuard`; 5 MB 업로드 상한 | AI 비용 남용은 `MAX_AI_MESSAGES_PER_DAY`로 부분 제한 |
| **권한 상승** | 서브 관리자 상승; 개방형 가입 | `PermissionGuard`; 민감 권한 부여 불가 | 개방형 관리자 가입 — §5.1 |

## 5. 알려진 약점 및 완화

### 5.1 개방형 관리자 가입 (높음)

`POST /admin/auth/signup`은 부트스트랩을 위해 의도적으로 미인증 상태
이며, 첫 가입이 `superadmin`이 된다. **공개 배포 전** 반드시 차단해야
한다: 첫 사용 후 라우트 비활성화, 초대 토큰 요구, 또는 네트워크/IP
제한.

### 5.2 `sessionStorage`의 관리자 토큰 (중간)

관리자 패널은 액세스/리프레시 토큰을 `sessionStorage`에 저장하여
패널의 모든 XSS에 노출시킨다. httpOnly 쿠키 대비 문서화된 트레이드
오프이다. 완화: CSRF 토큰과 함께 httpOnly·`Secure`·`SameSite` 쿠키로
이전하거나, 엄격한 CSP와 의존성 위생으로 위험을 수용.

### 5.3 전송 일관성 (중간)

로그인 이후 요청을 포함한 모든 API 트래픽은 HTTPS여야 한다. 비인증
엔드포인트를 HTTP로 제공하면 베어러 토큰(자격 증명)이 매 요청마다
노출되며, 로그인만 암호화하는 것은 실질적 보호를 제공하지 않는다.
HTTP→HTTPS 리디렉션과 함께 전 구간 HTTPS를 시행하라.

### 5.4 CORS 폴백 (낮음)

`CORS_ORIGINS`가 비어 있으면 백엔드는 전체 허용(`origin: true`)으로
폴백한다. 프로덕션에서는 항상 명시적 허용 목록을 설정하라.

### 5.5 Android 릴리스 서명 (중간)

릴리스 APK가 현재 디버그 키로 서명된다. 배포 전 프로덕션 키스토어를
구성해야 한다.

### 5.6 비밀값 위생 (낮음)

`docker-compose.yml`은 개발용 DB 비밀번호(`dev_password`)를 하드코딩
한다. `.env.example`은 플레이스홀더 비밀값을 제공한다. 프로덕션
비밀값이 고유·강력하며 절대 커밋되지 않도록 하라.

### 5.7 gzip 차단 스위치 비활성화 (정보)

런타임 gzip 차단 스위치가 주석 처리되어 있다. 취약점은 아니나 운영
정확성을 위해 기록한다.

| 기본 인증 적용 | 구현됨 |

## 7. 권고 사항 (우선순위순)

1. 공개 배포 전 `POST /admin/auth/signup` 차단.
2. 전체 API 표면에 HTTPS 시행.
3. 관리자 토큰을 httpOnly 쿠키로 이전하거나 엄격한 CSP 적용.
4. 프로덕션 Android 키스토어 구성.
5. 명시적 `CORS_ORIGINS` 허용 목록 항상 설정.
6. 프로덕션을 위해 모든 기본/예시 비밀값 회전.
