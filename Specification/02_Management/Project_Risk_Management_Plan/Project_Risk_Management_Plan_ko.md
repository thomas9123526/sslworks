# 프로젝트 및 리스크 관리 계획

**프로젝트:** vLearn2 (VFLS) · **버전:** 1.0 · **작성일:** 2026-05-22

---

## 1. 목적

본 계획은 vLearn2 프로젝트가 어떻게 조직되고, 작업이 어떻게 진행되며,
리스크가 어떻게 식별·평가·통제되는지를 기술한다. 살아 있는 문서이며
매 릴리스마다 개정되어야 한다.

## 2. 범위

vLearn2 — Flutter 앱, NestJS 백엔드, Next.js 관리자 패널, DataManage
패키징 도구, PostgreSQL 데이터베이스로 구성된 크로스 플랫폼 회화 중심
언어 학습 제품.

## 3. 조직 및 역할

| 역할 | 책임 |
|------|------|
| 프로덕트 오너 | 우선순위, 범위, 성공 지표 |
| 백엔드 엔지니어 | NestJS API, 데이터 모델, AI 연동 |
| 프론트엔드 엔지니어(앱) | Flutter 앱, UX, 기기 내 음성 |
| 프론트엔드 엔지니어(관리자) | Next.js 관리자 패널 |
| QA | 테스트 설계·실행, 커버리지 추적 |
| 운영 | 배포, 모니터링, 인시던트 대응 |

소규모 팀에서는 한 사람이 여러 역할을 맡을 수 있으나 책임은 동일하게
적용된다.

## 4. 수명주기 및 주기

vLearn2는 반복적으로 개발된다. 각 변경은 계획 → 구현 → 검토 →
테스트(CI) → 병합 → 배포를 따른다. 저장소에는 계획 문서와 작업별
구현 보고서(`todoList/`, `todoList_report/`)가 작업 이력으로 포함되어
있다.

**브랜칭 / CI:** 경로 필터링 GitHub Actions가 각 서브시스템을 빌드·
테스트한다. *조치 항목:* 워크플로가 `master`/`dev`에서 트리거되나
기본 브랜치는 `main`이다 — 변경이 실제로 테스트되도록 정렬하라.

## 5. 마일스톤

| 마일스톤 | 완료 정의 |
|----------|-----------|
| M1 — 핵심 플랫폼 | 인증, 데이터 모델, 회화+채점이 종단간 동작 |
| M2 — 콘텐츠 & 게임화 | 시나리오, 코스, 진행도, 업적, 뉴스 |
| M3 — 관리 & 운영 | 관리자 패널, RBAC, 감사, 런타임 구성 |
| M4 — 음성 & 오프라인 | `.ddp`를 통한 기기 내 STT/TTS, 오프라인 읽기 캐시 |
| M5 — 출시 강화 | 보안 격차 해소(§7), 테스트 커버리지 목표 달성, 프로덕션 배포 |

M1–M4는 상당 부분 구현되었으며, M5가 미해결 작업이다.

## 6. 리스크 관리 프로세스

1. **식별** — 리스크는 지속적으로 제기되어 등록부(§7)에 기록된다.
2. **평가** — 각 리스크는 발생 가능성 × 영향(낮음/중간/높음)으로
   평가된다.
3. **계획** — 대응을 선택한다: 완화, 수용, 전가, 회피.
4. **추적** — 등록부는 매 릴리스마다 검토되며, 상태와 잔여 위험이
   갱신된다.
5. **에스컬레이션** — 높은 노출 리스크는 프로덕트 오너에게
   에스컬레이션된다.

## 7. 리스크 등록부

| ID | 리스크 | 가능성 | 영향 | 대응 |
|----|--------|--------|------|------|
| R-1 | 출시 전 개방형 관리자 가입 악용 | 중간 | 높음 | **완화** — 공개 배포 전 `admin/auth/signup` 차단 |
| R-2 | HTTP/HTTPS 혼합이 토큰 노출 | 중간 | 높음 | **완화** — 전체 API에 HTTPS 시행 |
| R-3 | `sessionStorage` 관리자 토큰이 XSS로 탈취 | 낮음 | 높음 | **완화/수용** — httpOnly 쿠키 또는 엄격한 CSP |
| R-4 | AI 제공자 장애 또는 비용 급증 | 중간 | 중간 | **완화** — 대체 응답; `MAX_AI_MESSAGES_PER_DAY` 상한 |
| R-5 | 얕은 자동화 커버리지로 회귀 출시 | 높음 | 중간 | **완화** — 테스트 명세서 §7 격차 해소 계획 실행 |
| R-6 | `main`에서 CI 미트리거 | 높음 | 중간 | **완화** — 워크플로 트리거 브랜치 정렬 |
| R-7 | Android 릴리스가 디버그 키로 서명 | 중간 | 높음 | **완화** — 프로덕션 키스토어 구성 |
| R-8 | 음성 모델 게이팅; `.ddp` 없이 음성 불가 | 중간 | 중간 | **수용/완화** — 텍스트 전용 대체; 명확한 설정 흐름 |
| R-9 | AI 세션 시작 경로 미구현 | 중간 | 낮음 | **완화** — AI 연동 완성 |
| R-10 | 문서 불일치(오래된 README, 포트 불일치) | 중간 | 낮음 | **완화** — 문서와 `cmds/` 스크립트 정리 |
| R-11 | 단일 CA / 비밀값 손상 | 낮음 | 높음 | **완화** — 가능한 한 비밀값을 호스트 밖에 보관; 회전 계획 |
| R-12 | 단일 운영 인력 — 버스 팩터 | 중간 | 중간 | **완화** — 본 문서 세트; 교차 교육 |

## 8. 품질 관리

- 변경의 **완료 정의:** 구현, 검토, CI 통과(린트, 빌드, 테스트),
  영향받는 문서 갱신.
- **커버리지:** 테스트 명세서 목표 대비 추적.
- **회귀:** 모든 결함 수정에 테스트를 추가(수정 전 실패, 후 통과).

## 9. 커뮤니케이션 및 변경 통제

- 범위 및 요구사항 변경은 수용 전 SRS와 요구사항 추적 매트릭스에 대해
  평가된다.
- 인터페이스 변경은 인터페이스 통제 문서의 변경 통제 절차를 따른다.
- 릴리스 결정은 배포 런북의 프로덕션 준비 체크리스트에 대해 내려진다.

## 10. 가정

- 팀 규모와 주기는 소규모로 유지된다.
- 외부 AI 제공자는 가용하며 예산 내에 있다.
- 대상 플랫폼은 v1.0에서 Android와 Windows로 유지된다.
