# 상세 테스트 케이스

**프로젝트:** vLearn2 (VFLS) · **버전:** 1.0 · **작성일:** 2026-05-22

본 문서는 테스트 명세서의 테스트 케이스 카탈로그를 실행 가능한 케이스
— 각각 전제 조건, 단계, 기대 결과 — 로 확장한다. 케이스는 영역별로
그룹화되며, ID는 테스트 명세서 및 요구사항 추적 매트릭스와 일치한다.

**템플릿 필드:** ID · 추적(FR/NFR) · 우선순위 · 전제 조건 · 단계 ·
기대 결과.

---

## 1. 인증

### TC-AUTH-1 — 학습자 가입 (정상 경로)
- **추적:** FR-AUTH-1 · **우선순위:** P1
- **전제 조건:** 선택한 `cidUsername`에 대한 계정이 없음.
- **단계:** 1) 유효한 `cid`, `cidUsername`, `password`(≥6),
  `displayName`, `uiLanguage`로 `POST /api/auth/signup`.
- **기대:** `201`; 응답에 액세스+리프레시 토큰 포함; `users` 행과
  `vl_user_info` 행 생성됨.

### TC-AUTH-2 — 가입이 짧은 비밀번호 거부
- **추적:** FR-AUTH-1 · **우선순위:** P1
- **단계:** 5자 비밀번호로 `POST /api/auth/signup`.
- **기대:** `400`; 검증 오류; 계정 미생성.

### TC-AUTH-3 — 로그인 (정상 경로)
- **추적:** FR-AUTH-2 · **우선순위:** P1
- **전제 조건:** 학습자 계정 존재.
- **단계:** 올바른 자격 증명으로 `POST /api/auth/signin`.
- **기대:** `200`; 액세스+리프레시 토큰 반환.

### TC-AUTH-4 — 로그인이 잘못된 자격 증명 거부
- **추적:** FR-AUTH-2 · **우선순위:** P1
- **단계:** 잘못된 비밀번호로 `POST /api/auth/signin`.
- **기대:** `401`; 오류 본문에 `i18nKey` `auth.invalid_credentials`;
  토큰 없음.

### TC-AUTH-5 — 갱신이 토큰을 회전
- **추적:** FR-AUTH-3 · **우선순위:** P1
- **전제 조건:** 유효한 리프레시 토큰 보유.
- **단계:** 리프레시 토큰으로 `POST /api/auth/refresh`.
- **기대:** `200`; 새 액세스 토큰; 새 리프레시 토큰(입력과 다름).

### TC-AUTH-6 — 사용된 리프레시 토큰 거부
- **추적:** FR-AUTH-3 · **우선순위:** P1
- **단계:** 1) 한 번 갱신(TC-AUTH-5). 2) *원본* 토큰으로 다시 갱신.
- **기대:** `401`; 소비된 토큰은 무효.

### TC-AUTH-8 — 만료된 액세스 토큰 거부
- **추적:** FR-AUTH-5 · **우선순위:** P1
- **단계:** 만료된 액세스 토큰으로 보호 라우트 호출.
- **기대:** `401`.

### TC-AUTH-9 — 토큰 누락 거부
- **추적:** FR-AUTH-5 · **우선순위:** P1
- **단계:** `Authorization` 헤더 없이 보호 라우트 호출.
- **기대:** `401`.

### TC-AUTH-10 — 관리자 비밀번호 정책
- **추적:** FR-AUTH-7 · **우선순위:** P1
- **단계:** 8자 소문자 전용 비밀번호로 `POST /api/admin/auth/signup`.
- **기대:** `400`; 12자 혼합 정책 미충족으로 거부.

### TC-AUTH-11 — 첫 관리자가 superadmin
- **추적:** FR-AUTH-8 · **우선순위:** P1
- **전제 조건:** 관리자 계정 없음.
- **단계:** 관리자 A 생성, 이어서 관리자 B 생성.
- **기대:** A는 `superadmin` 역할; B는 `admin` 역할.

## 2. 프로필

### TC-PROF-3 — 올바른 현재 비밀번호로 변경
- **추적:** FR-PROF-3 · **우선순위:** P1
- **단계:** 올바른 현재 비밀번호와 유효한 새 비밀번호로
  `PATCH /api/users/profile`.
- **기대:** `200`; 이후 로그인은 새 비밀번호로만 동작.

### TC-PROF-4 — 잘못된 현재 비밀번호로 변경 거부
- **추적:** FR-PROF-3 · **우선순위:** P1
- **단계:** 잘못된 현재 비밀번호로 `PATCH /api/users/profile`.
- **기대:** `400`/`401`; 비밀번호 변경 안 됨.

## 3. 콘텐츠 탐색

### TC-CONT-2 — 시나리오 목록이 게시된 것만 반환
- **추적:** FR-CONT-2 · **우선순위:** P1
- **전제 조건:** `draft`, `published`, `archived` 시나리오 존재.
- **단계:** `GET /api/scenarios`.
- **기대:** `published` 시나리오만 반환됨.

### TC-CONT-3 — 시나리오 필터
- **추적:** FR-CONT-2 · **우선순위:** P2
- **단계:** `GET /api/scenarios?category=...&difficulty=...&q=...`.
- **기대:** 결과가 제공된 모든 필터와 일치.

## 4. 회화 & 채점

### TC-CONV-1 — 자유 대화 세션 시작
- **추적:** FR-CONV-1 · **우선순위:** P1
- **단계:** `scenarioId` 없이 `personaId`와 `mode`로
  `POST /api/conversations/sessions`.
- **기대:** `201`; `scenario_id`가 null인 세션 생성.

### TC-CONV-3 — 메시지 전송이 튜터 응답 반환
- **추적:** FR-CONV-3 · **우선순위:** P1
- **전제 조건:** 활성 세션 존재; AI 제공자가 성공하도록 스텁됨.
- **단계:** 내용과 함께 `POST /api/conversations/sessions/:id/messages`.
- **기대:** `200/201`; 튜터 응답 반환; 사용자·어시스턴트 메시지가
  올바른 `role`·`sequence`로 영속화됨.

### TC-CONV-4 — 초과 길이 메시지 거부
- **추적:** FR-CONV-3 · **우선순위:** P2
- **단계:** 5001자 메시지 전송.
- **기대:** `400` 검증 오류.

### TC-CONV-7 — 세션 종료가 지표 기록
- **추적:** FR-CONV-6 · **우선순위:** P1
- **단계:** `POST /api/conversations/sessions/:id/end`.
- **기대:** 세션 `status=completed`; `duration_seconds`,
  `turn_count`, `word_count`, `xp_earned` 채워짐.

### TC-CONV-10 — 제공자 실패 시 AI 대체
- **추적:** FR-CONV-8, NFR-REL-2 · **우선순위:** P1
- **전제 조건:** AI 제공자가 예외를 던지도록 스텁됨.
- **단계:** 활성 세션에서 메시지 전송.
- **기대:** `200`; 미리 준비된 대체 응답 반환; 클라이언트에 오류 미노출.

### TC-SCORE-1 — 다중 스킬 점수 산출
- **추적:** FR-SCORE-1 · **우선순위:** P1
- **단계:** 세션을 완료하고 점수를 읽음.
- **기대:** `overall_score`와 해당 스킬별 점수를 가진
  `vl_session_scores` 행.

## 5. 관리 & RBAC

### TC-ADM-3 — 사용 중인 카테고리 삭제 거부
- **추적:** FR-ADM-3 · **우선순위:** P2
- **전제 조건:** 시나리오 1건 이상이 참조하는 카테고리.
- **단계:** `DELETE /api/admin/categories/:id`.
- **기대:** `409`; 카테고리 미삭제.

### TC-ADM-11 — 민감 권한 부여 불가
- **추적:** FR-ADM-12 · **우선순위:** P1
- **단계:** superadmin으로서 부여 불가 권한을 서브 관리자에게 부여 시도.
- **기대:** 거부됨; 권한 미부여.

### TC-ADM-12 — 권한 없는 서브 관리자 거부
- **추적:** FR-ADM-16 · **우선순위:** P1
- **전제 조건:** `scenarios.edit`가 없는 서브 관리자.
- **단계:** 해당 서브 관리자로 `POST /api/admin/scenarios`.
- **기대:** `403`.

### TC-ADM-14 — 관리 변경이 감사 항목 기록
- **추적:** FR-ADM-14 · **우선순위:** P1
- **단계:** 임의의 관리 변경 수행(예: 시나리오 게시).
- **기대:** 행위자·행위·대상·변경 전/후 값을 가진 `vl_admin_audit_log`
  행.

### TC-ADM-15 — 실패한 변경이 감사 항목 없이 롤백
- **추적:** FR-ADM-14, NFR-REL-3 · **우선순위:** P1
- **단계:** 트랜잭션 도중 실패하는 관리 변경을 유발.
- **기대:** 데이터 변경 없음, 감사 항목 없음 — 둘 다 롤백됨.

## 7. 비기능

### TC-NFR-SEC-3 — 보호 라우트가 익명 접근 거부
- **추적:** NFR-SEC-3 · **우선순위:** P1

- **추적:** NFR-REL-1 · **우선순위:** P1
- **단계:** `GET /health`.
- **기대:** `200`; 본문 `{ "status": "ok" }`.

### TC-NFR-SEC-4 — 속도 제한
- **추적:** NFR-SEC-5 · **우선순위:** P2
- **단계:** 윈도우 내에서 구성된 요청 한도를 초과.
- **기대:** 한도 초과 시 `429`.

## 8. 참고

- 여기에 개별 기재되지 않은 케이스(전체 카탈로그는 테스트 명세서
  §5–6)는 동일한 템플릿을 따른다; 자동화될 때 확장하라.
- AI 의존 케이스는 결정성을 위해 제공자를 스텁해야 한다.
- 음성/`.ddp` 케이스는 DataManage 바이너리와 CA 파일이 필요하며,
  없으면 자체적으로 건너뛴다.
