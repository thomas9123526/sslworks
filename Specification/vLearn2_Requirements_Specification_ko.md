# 소프트웨어 요구사항 명세서

**프로젝트:** vLearn2 — 제품명 *Virtual Foreign Language* (VFLS)
**문서 종류:** 소프트웨어 요구사항 명세서 (SRS)
**버전:** 1.0 (초안)
**작성일:** 2026-05-22
**근거:** `C:\project\vLearn2`의 구현된 동작으로부터 재구성.

## 1. 개요

### 1.1 목적

본 문서는 vLearn2 시스템의 기능 및 비기능 요구사항을 명세한다. 시스템이
*무엇을*, *누구를 위해*, *어떤 제약 하에서* 수행하는지를 정의한다. 동반
문서인 시스템 설계 명세서는 시스템이 *어떻게* 구축되는지를 기술하며,
테스트 명세서는 요구사항이 어떻게 검증되는지를 정의한다.

시스템이 이미 존재하므로, 본 SRS는 구현된 동작으로부터 재구성되었으며,
유지보수·회귀 테스트·향후 변경 관리를 위한 기준선으로 사용된다.

### 1.2 범위

vLearn2는 영어 연습을 위한 회화 중심 언어 학습 플랫폼이다. 학습자는 AI
튜터 페르소나와 영어 회화(음성 또는 텍스트)를 — 자유 형식 또는 역할극
시나리오 기반으로 — 수행하고, 자동 다중 스킬 채점, 진행도 추적,
연속 학습일, 업적을 받는다. 운영 인력은 웹 관리자 콘솔을 통해 학습
콘텐츠, 사용자, AI 프롬프트, 런타임 설정을 관리한다.

제품은 Flutter 앱(Android 및 Windows), NestJS 백엔드 API, Next.js
관리자 패널, 오프라인 DataManage 패키징 도구로 제공되며, PostgreSQL이
이를 뒷받침한다.

### 1.3 용어 및 약어

| 용어 | 의미 |
|------|------|
| 학습자(Learner) | Flutter 앱의 최종 사용자 |
| 관리자/서브 관리자/슈퍼관리자 | 권한 수준별 관리자 패널 운영 인력 |
| 페르소나 | AI 튜터 캐릭터 |
| 시나리오 | 구조화된 역할극 회화 연습 |
| 코스 | 순서화된 시나리오 집합 |
| 세션 | 학습자와 튜터 간 한 번의 회화 |
| 자유 대화(Free talk) | 시나리오에 묶이지 않은 세션 |
| XP | 경험치 |
| Streak | 연속 활동 일수 |
| FR / NFR | 기능 / 비기능 요구사항 |
| `.ddp` | DataManage가 생성한 서명된 음성 모델 번들 |

### 1.4 참고 문서

- vLearn2 시스템 설계 명세서.
- vLearn2 테스트 명세서.
- 백엔드 OpenAPI 명세(`/api/docs`).

### 1.5 요구사항 표기

기능 요구사항은 `FR-<영역>-<번호>`로, 비기능 요구사항은
`NFR-<범주>-<번호>`로 식별한다. "**해야 한다(shall)**"는 필수
요구사항을 나타낸다.

## 2. 전체 설명

### 2.1 제품 관점

vLearn2는 독립적인 클라이언트–서버 제품이다. Flutter 앱과 관리자
패널은 단일 백엔드 API의 클라이언트이며, 백엔드는 외부 AI
제공자(Anthropic 또는 OpenAI 호환 서비스) 및 파일 스토리지(로컬 디스크
또는 S3)와 연동된다. PostgreSQL이 기록 원본이다. DataManage 도구는
음성 모델을 패키징하기 위해 오프라인으로 동작한다.

### 2.2 사용자 분류

| 사용자 분류 | 설명 | 주요 인터페이스 |
|-------------|------|-----------------|
| 학습자 | 언어를 연습하고 진행도를 추적 | Flutter 앱 |
| 서브 관리자 | 일부 권한을 부여받은 운영 인력 | 관리자 패널 |
| 관리자 | 폭넓은 콘텐츠/사용자 권한을 가진 운영 인력 | 관리자 패널 |
| 슈퍼관리자 | 제한 없는 운영 인력; 다른 관리자 관리 | 관리자 패널 |
| 콘텐츠 패키저 | 음성 모델 번들 생성 | DataManage 도구 |

### 2.3 운영 환경

- **Flutter 앱:** Android(최소 SDK 24) 및 Windows 데스크톱.
- **관리자 패널:** 최신 데스크톱 웹 브라우저.
- **백엔드:** Linux(RHEL 계열) 또는 Windows의 Node.js 22+.
- **데이터베이스:** PostgreSQL 16.
- **리버스 프록시:** TLS를 종단하는 nginx.

### 2.4 설계 및 구현 제약

- 백엔드는 `/api` 접두사 아래 REST API를 노출하며, nginx가 공개
  `/vfls/*` 경로를 이에 매핑하고 관리자 패널을 `/vAdmin/*` 아래에서
  제공한다.
- 인증은 회전식 리프레시 토큰을 가진 JWT 액세스 토큰을 사용한다.
- 지역화 콘텐츠는 다국어를 지원해야 한다(현재 앱에는 영어와 중국어가
  탑재됨).
- Flutter 앱은 오프라인 시 로컬 캐시를 사용하여 읽기 전용 모드로
  동작해야 한다.
- 기기 내 음성은 설치된 서명 `.ddp` 모델 번들을 필요로 한다.

### 2.5 가정 및 의존성

- 실시간 튜터 응답 및 AI 기반 채점에는 접근 가능한 AI 제공자가
  필요하며, 불가용 시 시스템은 대체 동작으로 성능 저하한다.
- 음성 모델을 설치하는 학습자는 유효한 `.ddp` 번들에 접근할 수 있다.
- 모든 쓰기 작업에는 네트워크 연결이 가능하다.

## 3. 기능 요구사항

### 3.1 인증 및 계정

**FR-AUTH-1** — 시스템은 학습자가 필수 자격 증명 및 프로필 필드를
제공하여 계정을 생성할 수 있도록 해야 한다. 학습자 비밀번호는 최소
6자여야 한다.

**FR-AUTH-2** — 시스템은 학습자가 로그인하여 단기 액세스 토큰과
리프레시 토큰을 받을 수 있도록 해야 한다.

**FR-AUTH-3** — 시스템은 유효한 리프레시 토큰을 새 액세스 토큰으로
교환할 수 있도록 해야 하며, 각 리프레시 토큰은 1회용이고 교환 시
회전되어야 한다.

**FR-AUTH-4** — 시스템은 학습자가 로그아웃하여 현재 리프레시 토큰을
무효화할 수 있도록 해야 한다.

**FR-AUTH-5** — 시스템은 만료되었거나 유효하지 않은 토큰을 거부하고
재인증을 요구해야 한다.

**FR-AUTH-6** — Flutter 앱은 학습자의 선택에 따라 편의를 위해 학습자
자격 증명을 선택적으로 기억해야 한다.

**FR-AUTH-7** — 시스템은 관리자가 계정을 생성할 수 있도록 해야 한다.
관리자 비밀번호는 최소 12자이며 소문자·대문자·숫자를 포함해야 한다.

**FR-AUTH-8** — 최초로 생성된 관리자 계정은 `superadmin` 역할을
부여받아야 하며, 이후 관리자 계정은 기본적으로 `admin`이어야 한다.

### 3.2 학습자 프로필

**FR-PROF-1** — 시스템은 학습자가 레벨, 총 XP, streak, 환경설정을
포함한 프로필을 조회할 수 있도록 해야 한다.

**FR-PROF-2** — 시스템은 학습자가 표시 이름, 아바타, 성별,
모국어/UI 언어, 테마, 활성 페르소나를 수정할 수 있도록 해야 한다.

**FR-PROF-3** — 시스템은 학습자가 현재 비밀번호 증명을 요구받으며
비밀번호를 변경할 수 있도록 해야 한다.

**FR-PROF-4** — 시스템은 학습자의 온보딩 완료 여부를 기록하고,
완료되기 전까지만 온보딩을 제시해야 한다.

### 3.3 학습 콘텐츠 탐색

**FR-CONT-1** — 시스템은 억양, 스타일, 전문 분야, 아바타를 가진 활성
AI 튜터 페르소나 카탈로그를 제시해야 한다.

**FR-CONT-2** — 시스템은 카테고리, 난이도, 자유 텍스트 질의로 필터링
가능한 게시(published) 시나리오 카탈로그를 제시해야 한다.

**FR-CONT-3** — 시스템은 장면 설명, 역할, 목표, 핵심 표현, 예상 소요
시간, XP 보상을 포함한 시나리오 상세를 제시해야 한다.

**FR-CONT-4** — 시스템은 활성 시나리오 카테고리를 제시해야 한다.

**FR-CONT-5** — 시스템은 게시된 코스를 제시하고, 선택된 코스에 대해
정해진 순서로 시나리오를 제시해야 한다.

**FR-CONT-6** — 콘텐츠 텍스트는 지역화 텍스트가 존재하는 경우 학습자가
선택한 언어로 제시되어야 한다.

### 3.4 회화 세션

**FR-CONV-1** — 시스템은 학습자가 페르소나를, 그리고 선택적으로
시나리오를 선택하여 회화 세션을 시작할 수 있도록 해야 한다. 시나리오가
없는 세션은 자유 대화 세션이다.

**FR-CONV-2** — 시스템은 두 가지 회화 모드를 지원해야 한다: 텍스트
채팅과 애니메이션 아바타를 가진 튜터 "얼굴" 모드.

**FR-CONV-3** — 시스템은 학습자 메시지(1–5000자)를 받아 AI 튜터 응답을
반환해야 한다.

**FR-CONV-4** — 시스템은 모든 세션 메시지를 역할 및 순서 정보와 함께
영속화해야 한다.

**FR-CONV-5** — 시스템은 학습자가 유휴 상태일 때 추천 프롬프트를 요청할
수 있도록 해야 한다.

**FR-CONV-6** — 시스템은 학습자가 세션을 종료할 수 있도록 해야 하며,
소요 시간, 턴 수, 단어 수, 획득 XP를 기록해야 한다.

**FR-CONV-7** — 시스템은 학습자가 과거 세션을 조회·재진입하고 세션을
삭제할 수 있도록 해야 한다.

**FR-CONV-8** — AI 제공자가 불가용할 때 시스템은 오류 대신 우아한 대체
응답을 반환하여 회화가 계속 사용 가능하도록 해야 한다.

**FR-CONV-9** — 시스템은 학습자별 AI 기반 메시지의 일일 한도를 설정
가능한 형태로 시행해야 한다.

### 3.5 채점 및 피드백

**FR-SCORE-1** — 시스템은 해당하는 경우 종합, 발음, 유창성, 어휘, 문법,
참여도, 듣기 차원을 포괄하는 세션별 점수를 산출해야 한다.

**FR-SCORE-2** — 시스템은 강점과 개선 영역을 포함한 세션별 피드백을
산출해야 한다.

**FR-SCORE-3** — AI 문법 채점이 불가용할 때 시스템은 알고리즘 채점으로
대체해야 한다.

**FR-SCORE-4** — 시스템은 세션 종료 후 학습자에게 세션 리포트를
제시해야 한다.

### 3.6 진행도, Streak, 게임화

**FR-PROG-1** — 시스템은 종합 학습자 진행도(총 세션 수, 주간 세션 수,
말한 시간, 말한 단어 수, 완료 시나리오 수, 현재 streak, 최장 streak)를
유지해야 한다.

**FR-PROG-2** — 시스템은 일별 스킬별 스냅샷(발음, 유창성, 듣기, 어휘,
문법)을 유지하고, 당일 값은 이동 평균으로 갱신해야 한다.

**FR-PROG-3** — 시스템은 최고 점수와 완료 횟수를 포함한 시나리오별
완료 기록을 기록해야 한다.

**FR-PROG-4** — 시스템은 완료된 활동에 대해 XP를 부여하고 XP로부터
도출된 학습자 레벨을 유지해야 한다.

**FR-PROG-5** — 시스템은 업적 카탈로그를 유지하고 정의된 조건이
충족되면 학습자에게 업적을 부여해야 한다.

**FR-PROG-6** — 시스템은 학습자가 업적 카탈로그와 자신이 획득한 업적을
조회할 수 있도록 해야 한다.

### 3.7 뉴스 및 공지

**FR-NEWS-1** — 시스템은 인앱 뉴스 게시물을 페이지네이션하여
학습자에게 제시하고, 고정(pinned) 게시물을 상단에 노출해야 한다.

**FR-NEWS-2** — 시스템은 학습자별 읽음 상태를 추적하고 미읽음 수를
보고해야 한다.

**FR-NEWS-3** — 시스템은 학습자가 개별 게시물 또는 전체 게시물을 읽음
처리할 수 있도록 해야 한다.

### 3.8 애플리케이션 구성

**FR-CFG-1** — 시스템은 기능 노출을 중앙에서 제어할 수 있도록 앱에
노출되는 구성 플래그를 Flutter 앱에 제공해야 한다.

### 3.9 오프라인 동작 (Flutter 앱)

**FR-OFF-1** — Flutter 앱은 사용자, 시나리오, 세션, 메시지, 진행도,
설정, 레이아웃 구성을 로컬에 캐시해야 한다.

**FR-OFF-2** — 기기가 오프라인일 때 앱은 캐시된 읽기 전용 콘텐츠를
제공하고, 원시 오류 대신 사용자 안전 메시지를 제시해야 한다.

**FR-OFF-3** — 앱은 인증 토큰을 기기의 보안 스토리지에 저장해야 한다.

### 3.10 기기 내 음성

**FR-SPCH-1** — 앱은 검증된 음성 모델 번들이 설치된 경우 음성 인식
입력과 음성 합성 재생을 지원해야 한다.

**FR-SPCH-2** — 검증된 모델 번들이 설치되지 않은 경우, 앱은 학습자가
명시적으로 텍스트 전용 모드를 승인하지 않는 한 음성 지원 회화를 시작하기
전에 학습자를 모델 설정 화면으로 전환해야 한다.

**FR-SPCH-3** — 앱은 `.ddp` 모델 번들을 설치하기 전에 고정된 루트 CA에
대해 그 암호 서명을 검증해야 한다.

### 3.11 관리 — 콘텐츠 관리

**FR-ADM-1** — 시스템은 권한 있는 운영 인력이 시나리오를 생성·편집·게시
·보관·삭제할 수 있도록 해야 한다.

**FR-ADM-2** — 시스템은 권한 있는 운영 인력이 페르소나를 생성·편집·소프트
삭제·복원할 수 있도록 해야 한다.

**FR-ADM-3** — 시스템은 권한 있는 운영 인력이 카테고리를 생성·편집·삭제할
수 있도록 해야 하며, 사용 중인 카테고리의 삭제는 거부해야 한다.

**FR-ADM-4** — 시스템은 권한 있는 운영 인력이 시나리오 및 페르소나
이미지를 업로드할 수 있도록 해야 하며, 타입(`jpeg`/`png`/`webp`)과
크기(≤ 5 MB)를 검증해야 한다.

**FR-ADM-5** — 시스템은 권한 있는 운영 인력이 뉴스 게시물을 생성·편집
·게시·보관·삭제할 수 있도록 해야 한다.

**FR-ADM-6** — 시스템은 권한 있는 운영 인력이 AI 프롬프트 템플릿
(tutor-system, grammar, feedback)을 조회·편집할 수 있도록 해야 한다.

### 3.12 관리 — 사용자 및 분석

**FR-ADM-7** — 시스템은 권한 있는 운영 인력이 학습자 계정을 목록 조회·
상세 조회할 수 있도록 해야 한다.

**FR-ADM-8** — 시스템은 권한 있는 운영 인력이 학습자 계정을 정지·복원하고
학습자 비밀번호를 재설정할 수 있도록 해야 한다.

**FR-ADM-9** — 시스템은 요약 통계(총 사용자 수, 최근 30일 활성 사용자
수, 총 세션 수, 게시 시나리오 수)를 제시해야 한다.

**FR-ADM-10** — 시스템은 선택 가능한 지표(총 XP, streak 일수, 레벨)로
순위가 매겨진 학습자 리더보드를 제시해야 한다.

### 3.13 관리 — 운영 인력 및 거버넌스

**FR-ADM-11** — 시스템은 슈퍼관리자가 서브 관리자 계정을 생성하고 개별
권한을 부여·회수할 수 있도록 해야 한다.

**FR-ADM-12** — 시스템은 개인정보 민감 권한이 서브 관리자에게 부여될 수
없도록 제한해야 한다.

**FR-ADM-13** — 시스템은 슈퍼관리자가 관리자 계정을 정지·복원·소프트
삭제할 수 있도록 해야 한다.

**FR-ADM-14** — 시스템은 모든 관리 변경 행위를 행위자, 행위, 대상,
변경 전/후 값을 담은 불변 감사 로그에 기록하고, 권한 있는 운영 인력이
이를 검색할 수 있도록 해야 한다.

**FR-ADM-15** — 시스템은 권한 있는 운영 인력이 런타임 구성 플래그를
조회·편집하고, 개별 플래그를 기본값으로 재설정하며, (슈퍼관리자 전용)
전체 플래그를 재설정할 수 있도록 해야 한다.

**FR-ADM-16** — 관리자 패널은 역할/권한 기반의 UI 기능 노출을 시행해야
하며, 백엔드는 클라이언트 측 게이팅과 무관하게 권위 있게 인가를 시행해야
한다.

### 3.14 콘텐츠 안전

**FR-SAFE-1** — 시스템은 회화 콘텐츠에서 허용되지 않는 자료를 검사하고,
심각도·일치 용어·언어·출처와 함께 위반을 기록해야 한다.

**FR-SAFE-2** — Flutter 앱은 추가로 클라이언트 측 콘텐츠 가드를 적용해야
한다.

### 3.15 모델 패키징 (DataManage)

**FR-PKG-1** — DataManage 도구는 파일 디렉터리를 단일 `.ddp` 번들로
패키징해야 한다.

**FR-PKG-2** — 도구는 각 번들에 암호 서명을 해야 하며, 선택적으로
암호화 및/또는 압축해야 한다.

**FR-PKG-3** — 도구는 GUI와 선택적 CLI 모드를 통해 동작해야 한다.

## 4. 외부 인터페이스 요구사항

### 4.1 사용자 인터페이스

- **Flutter 앱** — 5탭 인터페이스(홈, 시나리오, 회화 이력, 진행도,
  설정)와 스플래시, 인증, 온보딩, 전체 화면 회화, 세션 리포트, 코스,
  뉴스, 음성 모델 설정 화면. UI는 다중 테마, 폰트 그룹, 채팅 말풍선
  스타일을 지원해야 한다.
- **관리자 패널** — 콘텐츠, 사용자, 프롬프트, 리더보드, 감사, 관리자,
  설정 페이지를 가진 사이드바 내비게이션 대시보드.

### 4.2 소프트웨어 인터페이스

- **REST API** — `/api` 아래의 HTTP/HTTPS 기반 JSON. `/api/docs`의
  OpenAPI 명세로 문서화.
- **AI 제공자** — 구성으로 선택되는 Anthropic 또는 OpenAI 호환 API.
- **파일 스토리지** — 구성으로 선택되는 로컬 디스크 또는 S3.
- **데이터베이스** — TypeORM을 통한 PostgreSQL 16.

### 4.3 통신 인터페이스

- 모든 클라이언트–서버 트래픽은 HTTP/HTTPS를 사용해야 하며, 프로덕션
  트래픽은 nginx에서 TLS 종단되어야 한다.
- CORS는 구성된 허용 출처 집합으로 제한되어야 한다.

## 5. 비기능 요구사항

### 5.1 보안

**NFR-SEC-1** — 비밀번호는 bcrypt 해시로만 저장되어야 한다.

**NFR-SEC-2** — 리프레시 토큰은 해시로만 저장되어야 하며 1회용이어야
한다.

**NFR-SEC-3** — 모든 API 라우트는 명시적으로 공개로 지정되지 않는 한
인증을 요구해야 한다.

**NFR-SEC-4** — 관리 행위는 서버에서 시행되는 역할/권한 검사로 인가되어야
한다.

**NFR-SEC-5** — 시스템은 API 요청에 속도 제한을 적용해야 한다(기본
클라이언트당 60초당 120요청).

**NFR-SEC-6** — 비밀값은 환경 구성으로 공급되어야 하며 저장소에 커밋되어서는
안 된다.

**NFR-SEC-7** — 음성 모델 번들은 설치 전 서명 검증되어야 한다.

**NFR-SEC-8** — 모든 회화 토큰(로그인 후 전달되는 자격 증명)은 암호화된
연결로만 전송되어야 한다.

### 5.2 성능

**NFR-PERF-1** — 백엔드는 적격 응답에 gzip 압축을 적용해야 한다.

**NFR-PERF-2** — Flutter 앱은 신선한 캐시가 존재하는 읽기 전용 화면에서
네트워크 왕복 없이 캐시된 콘텐츠를 제공해야 한다.

**NFR-PERF-3** — `.ddp` 번들 해제는 앱이 응답성을 유지하도록 UI 스레드
밖에서 실행되어야 한다.

### 5.3 신뢰성 및 가용성

**NFR-REL-1** — 백엔드는 라이브니스 점검을 위한 헬스 엔드포인트를
노출해야 한다.

**NFR-REL-2** — 시스템은 AI 제공자가 불가용할 때 대체 응답과 알고리즘
채점으로 대체하여 우아하게 성능 저하해야 한다.

**NFR-REL-3** — 관리 변경과 그 감사 로그 항목은 단일 트랜잭션 내에서
원자적으로 기록되어야 한다.

### 5.4 사용성

**NFR-USE-1** — Flutter 앱은 사용자 안전 오류 메시지를 제시해야 하며,
원시 기술 오류를 절대 노출해서는 안 된다.

**NFR-USE-2** — 지역화 콘텐츠는 가능한 경우 학습자가 선택한 언어로
표시되어야 한다.

**NFR-USE-3** — 앱은 최초 학습자를 위한 온보딩을 제공해야 한다.

### 5.5 이식성

**NFR-PORT-1** — Flutter 앱은 단일 코드베이스로 Android(SDK 24+)와
Windows 데스크톱에서 동작해야 한다.

**NFR-PORT-2** — 백엔드는 Linux 및 Windows 호스트에서 동작해야 한다.

### 5.6 유지보수성

**NFR-MAINT-1** — 백엔드는 도메인 로직을 독립적인 기능 모듈로 구성해야
한다.

**NFR-MAINT-2** — 데이터베이스 스키마 변경은 버전 관리된 마이그레이션을
통해 적용되어야 한다.

**NFR-MAINT-3** — AI 프롬프트 콘텐츠는 코드 변경 없이 데이터(프롬프트
템플릿)로 편집 가능해야 한다.

### 5.7 감사 가능성

**NFR-AUD-1** — 모든 관리 변경은 행위자, 행위, 대상, 타임스탬프,
변경 전/후 값과 함께 기록되어야 한다.

## 6. 제약사항 및 미해결 항목

다음 구현 격차는 요구사항 충족도에 영향을 미치므로 추적해야 한다(상세는
시스템 설계 명세서 §11 참조).

- AI 세션 시작 경로가 일부 미구현이며(플레이스홀더 시작 메시지),
  **FR-CONV-1**에 부분적으로 영향을 미친다.
- 기기 내 음성(**FR-SPCH-1**)은 모델 번들에 게이팅되며, 설치 전까지
  플레이스홀더 엔진을 사용한다.
- gzip 런타임 차단 스위치가 코드에서 비활성화되어 있어, **NFR-PERF-1**을
  현재 런타임에 끌 수 없다.
- `POST /admin/auth/signup`은 현재 부트스트랩을 위해 미인증 상태이다.
  **FR-AUTH-7/8**은 공개 배포 전 차단되어야 한다.
- 관리자 패널 토큰이 `sessionStorage`에 저장되며, **NFR-SEC-8**과
  관련된 문서화된 트레이드오프이다.
